### Fixed
- **Flaky phone sheet UI test** (Nov 23). The class feature description replayed its slide-open animation on every redraw, so a state update while `test/ui.js` aimed at Activate moved or replaced the button ("Element is not attached", main run Nov 22). It now animates only on the tap that opens it, which also stops it flickering on players' phones. The test presses Activate through `hover()`, which waits and retries, and checks a redraw does not replay the animation.
- **Shop layout UI test waits for layout** (Nov 23). `test/nov21-ui.js` now waits for the TV shop columns to settle before checking the merchant sits on the right, instead of reading the layout on the first frame (failed once in CI on PR #158).
- **Readable text everywhere** (Mike, Nov 22). Text that was hard to read on its background. Road cards on the world map were dark ink on a near-black card; the map's town list, the dungeon editor, the backdrop picker, Creature Designer tabs and "Nobody yet" notes had the same kind of problem. Dark panels on parchment now take the light palette from one theme rule, parchment muted text is a shade darker (4.5:1), and a new browser test (`test/contrast-ui.js`) checks every DM, TV, phone and co-DM page for faint text.

## [1.2.0] - 2026-11-18

First tagged release (`v1.2.0`): everything built since 1.1.0. Play game nights from a tag; update the laptop between sessions.

### Changed
- **Browser tests wait for what they need, not for a fixed time** (Mike, Nov 18). The UI tests had 79 fixed pauses (18 left); the ones that waited for a page or state change now wait for that change (`settled()` for entrance animations and `poll()` in `test/helpers.js`). What is left are press durations, screenshot pauses and "nothing should happen" checks, each marked. Root cause of the `strike-ui` mixed-chain failure: node positions were read while the strike card was still animating in.
- **Tests never touch the real `data/` and `uploads/`** (Nov 18). `npm test` and `npm run test:ui` now run through `test/run.js`, which gives every script its own temp folders, runs them all even after a failure, and prints a summary with the command to re-run only the failed ones. `src/config.js` also gives any script under `test/` a temp folder when it is run alone. Before, some tests created files and startup backups in the repo's `data/`.

- **Scenario seeder and session replay** (Mike, Nov 17, test tools only, no change for players).

Character ids, seat tokens and the room code are swapped for the new server's.

Unrevealed rooms one step past a revealed room show as fogged "???" cards on the TV and phones; DM notes never leave the DM. The DM builds the tree in Scene and fog (add rooms, ropes in and out, reveal, remove), clicks a room on the stage preview to edit it, and double-clicks to move the party. Phones see the board and a button for each way onward. A fresh table starts with an example dungeon. The board adapts as the party moves: on the TV and phones, levels two or more behind the party shrink to a trail of icons so the rooms ahead get more space, and cards glide to their new places.
- Teamwork puzzles (`src/puzzle.js`): the DM starts a riddle, a Caesar cipher or an order puzzle. Clues are split over the seated players (or sent to every phone, or held back), so the table has to talk it out. Phones send guesses; the DM marks wrong ones and confirms the solve. The TV shows the prompt, then the solution with a pop and a word-by-word reveal.
- NPC and faction relationship web (`src/web.js`): the DM draws NPCs, factions and places, and how each feels about the party or each other (-100 to +100). Faction nodes link to the reputation list. The DM reveals nodes and links as the story goes and turns the web on for the TV, which shows tiers only, never the number. Phones see nothing of the web.
- Initiative spotlight on phones: your turn buzzes and glows with a "Your turn" tag; the next in order gets a short "on deck" buzz. Reduce motion keeps the glow still.
- Handouts unfold like paper when they arrive on a phone or on the TV (new items only; the first load stays still).
- Rest rules per class (`src/rests.js`): Warlock pact slots refill on a short rest; Wizard Arcane Recovery returns up to half the level in slot levels; Fighter, Cleric, Druid and Paladin features refill on the rest they name; Lay on Hands waits for a long rest.
- Short rest hit dice: players set how many to spend in the camp pop-up. Each die heals a roll of its die plus CON, and the log shows the rolls.
- Class feature uses (Wild Shape, Channel Divinity, Lay on Hands points) show on the owner's phone sheet.
- World map (Phase G): the DM uploads a map picture and places towns and sites on it. Phones vote where to go, one vote each, and a strict majority of the seated party sends the party there (the DM closes a vote, or overrides it at any time). Travel takes a set number of real seconds, and the party token glides along the line on the TV and the phones. Flavour cards come up while travelling: the DM's own cards first, then a weighted auto table the DM can edit or switch off. The DM can veto any card after it shows, and reveal lore on it. Place info is shown to the table only once the DM reveals it. Phones can comment on cards. The DM can show the map on the TV. Code: `src/worldmap.js` (rules), `src/sockets/worldmap.js` (events and timer), `public/worldmap.js` (shared drawing).

- Table tools (Phase I, `src/table.js`): the DM can save and fire a cue deck (mode, light, backdrop, layers, one-shot sound, handout) in one tap; send a silent nudge to one phone, which buzzes and lets the player share it aloud or keep it; watch a DM-only spotlight meter that shows who has acted or spoken and flags quiet players; set bonds between characters, with DM reminders to call them back after two sessions; run a dread tension bar on the TV; plant foreshadowing hints and show paid-off payoffs in the recap; spend a framing token on the phone to add a detail to the canon on the TV; run a montage where every phone answers one prompt and the answers are revealed together on the TV; and pick one-tap TV layouts (auto, social, combat, exploration, rest). - Living world (phase K). The DM sets clocks that tick on events, between sessions and during travel, and each clock can move a town's or faction's standing when it fills. Towns hold standing that changes prices and whether traders serve the party (DM can force trade open or closed, and shops can be shut at night). Rumours spread along the roads between towns, can come out changed, and can move a town's standing when they arrive. Weather, light and tension interlock (weather is one shared value, `state.weather`, that the TV weather from phase B reads too): weather and night slow travel and dim sight, storms and night change encounter rates, and loud soundboard one-shots push a tension track. Every automated or DM change is listed with an Undo, and DM-only changes stay off phones and the TV.

### Fixed
- **Window mover** (Mike, Nov 18). Unlocked windows could not be dragged at all: the drag looked the window up with a selector that never matched.
- **Town map fading out while moving places** (Mike, Nov 18). Every update redrew the world map stage, so the town (and dungeon) pop-up faded in again and the town picture was painted again. A pop-up that is already up now stays put, loaded pictures are reused, and a dragged place keeps its new spot until the save comes back.
- **Strike gesture test** (CI): the phone waits for its attack button and is reloaded once if it sits on an old screen, instead of timing out.
- An error outside a socket handler (a timer or a failed background task such as a wiki push) no longer ends the server and drops every phone: it is logged once, the campaign is saved and the game keeps running (`src/safety.js`).
- Starting the game while it is already running says the port is in use, instead of printing a stack trace.
- The Creature Designer's wiki Folder and Token fields no longer cut off their text on 1280 and 1500 px wide screens.
- A roll call with a **secret DC** no longer gives the result away. The TV coloured each result green or red, and the public log tone, the dice log and the roll pop-up all carried the DC and pass or fail. Now only the DM sees the DC and the outcome (on the roll call card) until they call it. The TV's roll call banner also showed "DC undefined" for a secret DC and the raw skill key instead of its label; it now shows the label and the rules system's own DC name (Daggerheart's Difficulty, for example), and leaves the DC out when it is secret.
- Saving can no longer crash the server. On Windows a sync tool, antivirus or open editor can lock a data file for a moment; the save now retries, and a save that still fails is logged and tried again every 2 s until it lands instead of taking the table down. Closing the server's console window (or Ctrl+Break) now saves everything first, like Ctrl+C, and one file failing on exit no longer skips the others (`saver()` in `src/store.js`).
- Pages no longer freeze silently when the laptop drops off the Wi-Fi or the server restarts. The TV, DM page, co-DM page and phones show a small **Reconnecting to the table…** pill that slides down after 1.5 s without the laptop, turns green with **Back at the table** when the connection returns, then slides away (`public/conn.js`).
- The DM can no longer move creatures around in combat without using their movement. Dragging, arrow keys and clicking a tile all use the creature's movement (path cost over heights and terrain). The DM may still go past its speed: the movement count then shows how far over it is in red, on the map's Move button, the creature's Encounter card, the hero column and the right-click menu, and the DM's log notes it. On the 3D map, tiles past the creature's movement are red. Before initiative, set-up moves stay free; the Teleport tool stays free.
- Switching modes no longer spams the log (Mike, Nov 16, PR P). Pressing the mode you are already in does nothing, and quick switches replace the last mode line instead of stacking one per press, on the DM log, the TV and phones.
- DM screen text boxes and dropdowns are no longer cut off. A growing field in a narrow tools card keeps room for its whole value or placeholder and wraps onto its own line instead of being squeezed by the buttons beside it; text areas grow to fit their text. Road card auto-table entries wrap. A few fixed-width fields are wider and a few long placeholders are shorter (the full hint is on hover). `npm run test:ui` now checks every DM field in every mode, tab and part at 1280 and 1500 px.
- World map page: places were hard to select. The board was redrawn on every state update, which dropped clicks; it now redraws only when it changes and never under a press, and each place has a larger hit area.
- Battle map tokens vanished on phones and the TV: the framing-token count (Phase I) was sent under the same `tokens` field and overwrote the map positions. The count is now `framingTokens`.
- `test/gamepad.js` (the DM controller test) was never in a test script and had fallen behind the DM screen (folded cards, the dialogue box inside the live conversation, mode lines that replace each other). It is fixed and runs with `npm run test:ui`. The rest of the test list was checked against every test file and the git history: nothing had been dropped.
